# Domain docs

This repository uses a single-context layout:

- `CONTEXT.md`: domain glossary.
- `docs/adr/`: architectural decisions.

## Before exploring

Read the glossary and ADRs relevant to the work. If they do not exist,
proceed silently; domain-modeling creates them when terms or decisions
are resolved.

If a root `CONTEXT-MAP.md` is introduced later, follow its links to the
relevant contexts and their ADRs.

## Vocabulary

Use the glossary's canonical terms in issues, proposals, and tests.
Treat missing concepts as potential glossary gaps rather than silently
introducing conflicting terminology.

## Decisions

Surface conflicts with existing ADRs explicitly. Reference the
conflicting decision and explain why it may need reconsideration.
